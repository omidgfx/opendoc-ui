Documentation browser

OpenDoc UI renders any OpenAPI 3.0, 3.1, 3.2 or Swagger 2.0 document into a fully navigable reference. Endpoints are grouped by tag into a sidebar tree that respects your sorting, route-display, protection and deprecation preferences, so a large specification becomes an orderly, searchable index rather than an overwhelming list.

Every operation opens a documentation view that leaves nothing hidden: parameter tables with types, formats, patterns and examples; request-body context with encoding-type selection and explicit oneOf/anyOf branch chips; and a response matrix with per-status example objects, schema tables, enum values and deep-linkable anchors such as #response-200. Pattern constraints carry a built-in tester, so you can validate candidate values against the exact regular expression before ever sending a request.

The most demanding specifications — deeply nested objects, recursive trees, mutually referencing schemas, polymorphic discriminators — are handled with cycle-safe rendering. Recursive branches terminate at their boundary and are marked with a loop icon, keeping the matrix readable instead of letting it expand forever.

  • Tag-grouped endpoint tree with counts, protection and deprecation indicators
  • Distinct method colors for GET, POST, PUT, DELETE, PATCH, HEAD, OPTIONS
  • Parameter, request-body and response surfaces with examples and enums
  • Built-in regex pattern tester and response-code deep links
  • Cycle-safe rendering of recursive and composed schemas

Built-in API Runner

Documentation is passive; the Runner is active. OpenDoc UI executes genuine requests from the browser against the servers declared in your specification, so the gap between reading an endpoint and calling it disappears. Path, query, header and cookie parameters are rendered as inputs with their documented examples and constraints; request bodies can be composed in a recursive form editor or as raw JSON, including multipart file uploads and application/x-www-form-urlencoded payloads.

Authentication is first-class: bearer tokens, API keys in headers, queries or cookies, HTTP basic auth, OAuth flows with an authorization-code PKCE helper, and browser-managed cookies. The response panel shows status, headers, body and a persistent history of your last ten outcomes, with cancellation for long-running calls. Keyboard shortcuts — Ctrl+Enter to execute, Ctrl+S to save inputs — keep the workflow fluid.

A dedicated Runner Compatibility report analyzes the specification and states plainly what the browser Runner can and cannot do for it, so expectations are set before you press execute.

  • Real fetch-based execution with live response inspection
  • Recursive form editor, raw JSON, multipart and URL-encoded bodies
  • Bearer, API-key, basic, OAuth and cookie authentication
  • Response history, cancellation and saved inputs per endpoint
  • Runner Compatibility report with honest capability analysis

Schema explorer

Every model in components/schemas is one click away. The explorer offers search with letter filters, and each schema opens a modal with a unified property matrix — dotted paths such as customer.address.city, types, formats, patterns, required markers, descriptions and examples — plus a simulated example object generated per media type (JSON, XML, YAML or PHP array).

Composition is made legible: allOf constraints are presented as conjoined requirements, while oneOf and anyOf alternatives become selectable branches with their referenced names. Referenced schemas support one-click drill-down, and the whole graph remains navigable without losing your place — the modal stack remembers exactly where you came from.

  • Searchable schema index with letter filters
  • Unified property matrix with dotted paths and required markers
  • Simulated examples in JSON, XML, YAML and PHP array
  • Branch-aware allOf / oneOf / anyOf / discriminator rendering
  • Drill-down modal stack and TypeScript export

Code & type generation

From any operation, OpenDoc UI generates a ready-to-run request snippet in the language of your choice — curl, JavaScript fetch and axios, Python, Go, C#, PHP and Angular — with the endpoint's parameters, body and authentication included. Secrets are automatically redacted into placeholders, so generated code is safe to share by design.

For consumers, the schema set exports as clean TypeScript: interfaces, unions for discriminated models, null handling and generated example constants, delivered as a ZIP or a single file. Your types and your documentation can never drift apart, because both derive from the same source of truth.

  • Nine codegen targets, from curl to Angular
  • Automatic secret redaction in generated snippets
  • Full TypeScript model export with example constants
  • Single-file or ZIP delivery

Local notes & todos

Real API work happens beside the endpoints, not away from them. OpenDoc UI keeps specification-scoped Markdown notes and todos with fourteen theme-safe tones, attachable to any endpoint through a context menu, the endpoint notes sidebar, or the Local Notes page. Todos carry a persistent done state and can offer to hide their endpoint once every open todo is complete — a tidy way to track integration work in place.

Deletion is never destructive by accident: notes move to a per-specification Trash with restore, permanent delete and empty-trash actions. When an endpoint disappears from the specification — renamed, removed, or never present in an imported export — its notes surface in a dedicated Orphaned list where you can re-assign them to another endpoint or delete them deliberately. Everything exports to a JSON file and imports back with orphaned-note detection and clear cross-specification warnings.

  • Per-endpoint Markdown notes and todos with fourteen tones
  • Resizable notes sidebar in Documentation and Runner views
  • Trash with restore, permanent delete and empty
  • Orphaned-note recovery with endpoint re-assignment
  • JSON export/import with cross-spec warnings

Optional AI assistant

The assistant answers questions grounded in your actual specification — endpoints, schemas, parameters and responses — with citations you can verify. It can open endpoints, pre-fill the Runner and propose a request through an explicit action bridge, so the AI never invents behavior; it prepares the workspace and you stay in control of execution.

Deployment is flexible: connect directly to a CORS-enabled provider (OpenAI, Anthropic, Ollama, OpenRouter, or any OpenAI-compatible endpoint), or run the hardened server-side AI gateway included in the repository — token-authenticated, origin-allowlisted, rate-limited and timeout-bounded, with reference implementations for eight backend frameworks.

  • Grounded answers with citations from your spec
  • Safe Runner preparation through the action bridge
  • Direct provider mode or hardened gateway mode
  • Multiple conversations, model profiles and Markdown export

Workspace & navigation

Everything in OpenDoc UI is a shareable URL. Endpoint tabs, response codes, schema modals and search states live in the address bar via clean History API routes, so browser back/forward works naturally and a link captures precisely what you are looking at. Tabs support preview-and-pin behavior, split view for documentation and Runner side by side, and full persistence across sessions.

Specifications themselves are managed with care: local files keep a history, remote URLs load with caching and revalidation, and deployed configurations can present curated spec sets. IndexedDB is the primary persistence layer for specs, history, notes, panel widths and workspace configuration, with a localStorage fallback for constrained environments.

  • Deep-linkable tabs, responses, schemas and search
  • Preview/pin tabs and split Documentation + Runner view
  • Global search with method, tag and security filters
  • IndexedDB-first persistence with resilient fallback
  • Local, remote and configured specification modes

Themes

OpenDoc UI ships with more than fifteen hand-crafted editor themes — Default Slate, Darcula and more, each with light and dark variants — stored per specification and switchable instantly. Note tones are designed to remain readable in every theme, so your workspace looks composed no matter the lighting.

  • 15+ curated themes with light/dark variants
  • Per-spec theme preference and instant toggle
  • Theme-safe note tones throughout
