The assistant

Ask your API a question.
Get a cited answer.

The OpenDoc UI assistant answers from retrieved, redacted endpoint and schema context — grounded in your open specification, with source citations you can click straight into the docs. It can even prepare a request in the Runner for you.

  • Direct provider mode — OpenAI, Anthropic, Ollama, OpenRouter or any compatible endpoint, from the browser.
  • Hardened gateway mode — keys stay server-side, with origin allowlists, rate limits and timeouts. Nine framework examples included.
  • Skill packs & saved chats — Swagger/REST skills, conversations saved per specification, secrets redacted before anything is sent.
How grounding works
Which endpoints can change a pet's status, and do any need auth?
Two operations can modify status: POST /pet (create) and PUT /pet (update). Both require the petstore_auth OAuth2 scope write:pets. POST /pet/{petId} can also update it via form data.

Straight answers

The questions everyone asks first

Does OpenDoc UI require a backend server?
No. Documentation, Runner, schema explorer, notes, theming and code generation all run entirely in the browser. The only optional server components — the AI gateway and the downloader proxy — are strictly opt-in.
Are my specifications uploaded anywhere?
Never. Local files are parsed in the browser and stored only in your browser's local history. Nothing is uploaded and the original document is never modified. Remote URLs are fetched directly by your browser — no third party involved.
Does the Runner really send requests from my browser?
Yes — that's the point. Requests are composed from the specification and executed with the browser's fetch API against the server you select. Standard CORS rules apply, and the Runner Compatibility report tells you honestly what the browser can and cannot do for a given API.
Where do my AI provider keys go?
In direct mode, your browser talks to the provider you configure. In gateway mode, a hardened server gateway owns the credentials and enforces token auth, origin allowlists, rate limits and timeouts — the browser never sees the provider key.
