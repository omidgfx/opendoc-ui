The OpenDoc UI manual

A methodical walkthrough of everything the application can do — from the first specification you open to the most intricate notes and AI workflows.

Quick start

The fastest path to a working workspace is the live demo: it opens the bundled Petstore specification immediately, and you can load your own file on the spot. Locally, everything begins with two commands:

Terminal
# install and start the development server
npm ci
npm run dev      # http://localhost:3000

# production build and local preview
npm run build    # outputs a single bundle: dist/index.js
npm run preview

Both commands are shell-independent and run identically on Windows, macOS and Linux. Once the application is open, click Open specification and choose a file from your device — no account, no upload, nothing leaves your machine.

OpenDoc UI never uploads your specification anywhere. Files are parsed in the browser and kept in local history for your next visit.

Loading specifications

There are three ways a specification can appear in the workspace, and they can be combined freely:

1 · Local files

The default mode. Open any .json, .yaml or .yml descriptor from your device. Multi-file specifications are supported: select all related documents together and their references resolve in memory. Your opened files are kept in a local history, and the original document is never modified.

2 · Remote URLs

When the deployment enables “Load from URL”, paste any OpenAPI or Swagger URL into the remote loader. Remote documents are cached with ETag revalidation, and cross-origin failures show actionable CORS guidance. A downloader proxy template can be configured for networks where the browser cannot reach the API host directly.

3 · Configured specifications

Deployments can present curated specification sets through a config.json file or a build-time window.INITIAL_CONFIG — useful for teams that want a fixed catalog of internal APIs on an intranet page. Configured and local files can also coexist in a hybrid mode.

If a specification references external documents (for example ../policies.yaml), select all related files together or use a bundled document — unresolved references are reported clearly and scoped, never fatal.

Reading the documentation

The sidebar organizes endpoints by tag into folders you can expand, collapse, sort and filter. Clicking an endpoint opens the View Documentation tab, which walks through the operation methodically:

  • Request parameters — every path, query, header and cookie parameter with its type, format, pattern, required state and example, plus a pattern tester for constrained values.
  • Request Body Context — the encoding type selector, the body schema matrix, and oneOf/anyOf branch chips when the body itself is a combinator, so each alternative is inspected on its own.
  • Response Matrix — every status code with its example object, schema table, enum values and a navigator that jumps between responses; success codes are expanded by default, others collapse to keep the view focused.

Deep links make the documentation shareable at a granular level: the URL carries the endpoint, the active tab, the selected response and even the schema modal stack. Send a colleague a link and they land exactly where you were.

Running requests

The API Runner tab is where documentation becomes execution. The request form mirrors the specification precisely:

1

Fill the parameters

Path, query, header and cookie parameters appear as individual inputs with their documented examples and validation hints pre-filled where the specification defines them.

2

Compose the body

In Form mode, the recursive body editor renders the schema as nested fields — arrays, objects, oneOf/anyOf alternatives with named branches, and file uploads. Raw JSON mode offers a full editor with prettify, wrap and find tools.

3

Execute

Press Ctrl+Enter or the run button. The response panel shows status, headers and body, keeps your last ten outcomes in history, and lets you cancel in-flight calls.

4

Persist

Save inputs per endpoint with Ctrl+S; they are restored the next time you open the endpoint, including the exact oneOf branch you were editing.

Requests are sent directly from your browser to the selected server, so the same CORS considerations as any web application apply. The Runner reports what it can and cannot do in the compatibility report.

Authentication

OpenDoc UI covers the authentication schemes a specification can declare. Open the Authorize panel and configure:

  • Bearer tokens — sent as an Authorization header on protected operations.
  • API keys — in headers, query strings or cookies, exactly where the scheme declares them.
  • HTTP basic auth — username and password pairs.
  • OAuth 2.0 — including an authorization-code flow with PKCE that completes the callback natively.
  • Cookies — browser-managed session cookies are included when the endpoint uses cookie authentication.

Security state is per-specification and stored in memory — tokens never leave your machine unless you explicitly execute a request. The documentation and Runner surfaces show whether an operation is protected and whether your current credentials satisfy it.

Working with schemas

The Schema Explorer in the sidebar indexes every model in the specification. Selecting one opens its schema modal:

  • Scope Table — the unified property matrix: dotted paths, types, formats, patterns, required markers, examples and descriptions, with recursive rows marked by a loop icon.
  • Unified Simulation Example — a generated example object for the selected media type (JSON, XML, YAML, PHP array).
  • Enum Values — every permitted value as copyable chips when the schema is an enumeration.

Referenced schemas open as drill-downs in a modal stack; press Esc to walk back out. Composed schemas — allOf, oneOf, anyOf, discriminator — are rendered branch by branch so each alternative is comprehensible on its own.

Generating code & types

From an endpoint, open the code generator and choose your target language. The snippet is assembled from the specification — parameters, body and authentication — with secrets replaced by placeholders. From the schema explorer, export TypeScript: the generator produces typed interfaces for every model, plus example constants, downloadable as a ZIP or a single file.

Notes, trash & orphaned notes

Notes are private to your browser and scoped to the open specification. Create one from an endpoint's context menu, from the endpoint notes sidebar, or from the Local Notes page.

Everyday use

  • Notes render Markdown and carry one of fourteen theme-safe tones.
  • Todos persist a done state; completing the final open todo can offer to hide the endpoint.
  • The endpoint notes sidebar in Documentation and Runner views is resizable and remembers its width and expanded state.

Deletion is never final

Deleting a note moves it to the Trash — restore it, delete it permanently, or empty the trash entirely. Notes whose endpoint disappears from the specification land in the Orphaned list, where you can re-assign them to another endpoint through a searchable picker or remove them deliberately. Bulk actions such as “Move all to trash” only touch active notes; orphaned notes are never swept along.

Export and import

The Local Notes toolbar exports every note and todo as a JSON file (with source metadata and orphaned-note ids) and imports them back with a clear warning when the file came from a different specification. Matching notes merge in; unmatched ones land in the orphaned list where they await your decision.

The AI assistant

The topbar sparkle opens the assistant workspace. Ask questions about the API — the assistant retrieves redacted endpoint and schema context and answers with citations. It can also act: open an endpoint, fill the Runner, or propose a request, which you review before anything executes.

Configuration lives in global AI profiles: provider, model, keys, gateway settings, temperature, skills and custom instructions. In direct mode the browser talks to a CORS-enabled provider; in gateway mode it talks to the included hardened server gateway, which owns the provider credentials and enforces origin allowlists, rate limits and timeouts.

Themes & appearance

Open the theme selector to choose among more than fifteen editor themes — Default Slate, Darcula and others, each with light and dark variants. The choice is remembered per specification, and the instant light/dark toggle adapts the entire interface, including note tones, which are designed to stay readable in every theme.

Keyboard shortcuts

ShortcutAction
Ctrl / ⌘ + KFocus global search
Ctrl + EnterExecute the request in the Runner
Ctrl + SSave Runner inputs
Alt + ← / →Switch endpoint tabs
Ctrl + `Open the tab switcher
EscClose the top-most modal / walk back through the schema stack
Ctrl / ⌘ + ↓ / ↑Jump between response codes in the documentation

Shortcuts are active only where they make sense — for example, search is ignored while you are typing in an input, and response navigation requires the documentation pane to be focused.
